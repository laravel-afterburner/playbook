## Overview

Roles control what members can do within a {{ entity_label }}. Each member is assigned one or more roles for the {{ entity_label_plural }} they belong to.

## Default roles

Applications ship with role templates appropriate to the domain. For example, a strata application may include President, Secretary, Council Member, and Owner roles.

## Permissions

Each role grants a set of **permissions** — discrete abilities such as managing meetings, viewing documents, posting announcements, or managing finances. Permissions are grouped by area (Properties, Finances, Voting, and so on).

## Roles management page

Open **Roles** from your {{ entity_label }} menu (or the route your application exposes for role management) to:

- Review default and custom roles
- See which permissions each role includes
- Create custom roles with specific permission sets
- Configure role hierarchy when your application supports it

Use descriptive role names so members understand their responsibilities.

## {{ entity_label_title }} owners

The {{ entity_label }} owner always has full access within that {{ entity_label }}, regardless of assigned roles.

## Changing a member's role

Open the **Members** page, select a member, and update their assigned role. Changes take effect immediately.
