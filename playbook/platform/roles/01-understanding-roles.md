## Overview

Roles control what members can do within a {{ entity_label }}. Each member is assigned one or more roles for the {{ entity_label_plural }} they belong to.

## Default roles

Applications ship with role templates appropriate to the domain. For example, a strata application may include President, Secretary, Council Member, and Owner roles.

## Permissions

Each role grants a set of **permissions** — discrete abilities such as managing meetings, viewing documents, or posting announcements. The Roles page lists available permissions grouped by area.

## {{ entity_label_title }} owners

The {{ entity_label }} owner always has full access within that {{ entity_label }}, regardless of assigned roles.

## Custom roles

Administrators can create custom roles with specific permission sets. Use descriptive names so members understand their responsibilities.

## Role hierarchy

Some applications support role hierarchy. Higher roles may manage lower roles. Configure hierarchy from the Roles management page.

## Changing a member's role

Open the Members page, select a member, and update their assigned role. Changes take effect immediately.
